# Pipeline Overview

## Назначение

`LLM Pipeline Demo` показывает, как из сырого поискового спроса можно получить структуру страниц и редакционные артефакты. Внутри это не production pipeline, а управляемая демонстрация этапов, метрик, конфликтов и решений.

## Логика пайплайна

### 1. Импорт

Демо-данные поступают из `data/demo-raw-queries.json`. Каждый объект содержит:

- `query`
- `source`
- `frequency`
- `geo`

### 2. Нормализация

Скрипт `scripts/pipeline-demo.mjs`:

- приводит запросы к нижнему регистру
- чистит пробелы
- убирает некоторые шумовые хвосты
- нормализует частные формулировки

### 3. Первичная классификация

Дальше применяется rule-based логика:

- мусорные запросы отклоняются
- support/informational кейсы маркируются на review
- comparison и geo-запросы получают warning-статусы
- коммерческие запросы идут дальше по пайплайну

### 4. Semantic Parsing

Для валидных строк демонстрация строит:

- сущность
- тип сущности
- атрибуты
- geo
- intent
- confidence
- review flag

Этот слой визуализируется в разделе semantic parsing интерфейса.

### 5. Кластеризация

Запросы группируются в смысловые единицы, из которых появляются:

- cluster id
- label
- page type candidate
- H1
- slug
- matched URL

### 6. Site Structure

Из кластеров собирается дерево потенциальных страниц:

- category
- filter-page
- brand-page
- guide-page
- comparison-page
- geo-page

### 7. URL Matching

Для каждого кластера демо показывает:

- рекомендованный slug
- найденный URL
- тип совпадения
- confidence
- действие: merge, review или create new

### 8. Human In The Loop

Спорные кейсы попадают в review queue. Это важная часть демонстрации: UI не делает вид, что LLM решает всё автоматически.

### 9. Content Briefs

На финальном этапе формируются кандидаты в страницы и контент-брифы для SEO, каталога или редакции.

## Откуда UI берёт данные

Есть два режима:

### Режим 1. Bundled demo data

Интерфейс использует значения из `src/data.ts`.

### Режим 2. Runtime demo data

Если существует `public/demo-run.json`, приложение загружает его при старте и подменяет встроенный набор данных.

## Архитектурная идея

Этот проект полезен как:

- презентационный стенд
- прототип для будущей админки
- иллюстрация SEO/LLM workflow
- основа для более серьёзного internal tool

## Что здесь пока отсутствует

- реальный LLM orchestration backend
- очереди задач
- долговременное хранилище
- авторизация
- история прогонов
- реальные API-вызовы к OpenAI/Cerebras из frontend
